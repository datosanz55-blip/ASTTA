# Автопроверка размеров, цены и фото

## Что исправлено

Карточка Poizon больше не отправляет покупателя в китайское приложение узнавать цену вручную. Выбор размера запускает фоновую проверку, UI показывает ожидание, затем подтверждённую цену или понятный результат «цена не подтверждена» с повтором и обращением к агенту. Форма заказа по ссылке получает фотографии и размеры, использует тот же механизм. DeepSeek получил инструмент `check_market_price`: результат и фото появляются под ответом без повторного запроса к модели.

Исправлены причины отсутствия фото: `inspect_link` теперь проверяет площадку также для найденного товара из каталога, форма и чат действительно отображают возвращённые фото. Внешние изображения идут через подписанный `/api/link/image` на нашем домене, поэтому проходят существующую CSP. Адреса ограничены CDN площадок, редиректы отключены, поток ограничен 10 МБ, файл проверяется и перекодируется в WebP. Произвольные URL картинок из текста ИИ не отображаются. Фотографии товаров из нашего каталога также доступны в ответе ИИ.

В прямом запросе Poizon явно передаётся `styleCodes: []`, чтобы значение по умолчанию из схемы Actor (`B75806`) не добавляло посторонний товар к запросу `spuIds`. При наличии ID в ответе проверяется его совпадение.

## Ограничение текущего источника — остаётся

На момент исследования подключены:

- Импорт каталога: [zen-studio/dewu-poizon-scraper](https://apify.com/zen-studio/dewu-poizon-scraper). Публичная документация прямо говорит: **China prices apply to the product, not individual sizes**. В `sizes[].officialRetailCny` лежит рекомендованная цена; `poizonPriceRub` относится к российскому POIZON, а не к выкупу на Dewu в Китае.
- Просмотр ссылки: [sian.agency/dewu-poizon-price-tracker](https://apify.com/sian.agency/dewu-poizon-price-tracker). Документация описывает `skus` как **per-SKU id, retail price, status, size property**. Наличие массива SKU не означает наличие актуальных предложений по каждому размеру.

Подтверждать произвольный размер по этим данным нельзя. Код принимает только явно названную live-цену SKU (`salePriceCny`, `lowestAskCny`, `minSalePriceCny` или документированную цену продажи в фэнях). Общая минимальная цена разрешается только для SKU, к которому поставщик явно привязал её через `lowestPriceSkuId`. `price`, `authPrice`, `officialRetailCny`, одинаковая «розничная» цена или пересчёт российской цены в юани не используются как цена выкупа размера.

**Для полного покрытия всех размеров нужен источник, который реально возвращает live CNY ask по выбранному SKU. Такой новый источник в этом PR не подключён.** Нужны подтверждённые документация и образец ответа: ID исходного товара, SKU, точная размерная система, цвет, наличие, цена продажи, валюта/единицы и время проверки. Проверять на нескольких товарах и размерах, включая отсутствующий в продаже. Покупка нового API, внешняя регистрация и изменение секретов на сервере не выполнялись. Тесты с API-моками проверяют наш сценарий, но не доказывают полноту данных платного провайдера.

При смене/обновлении источника адаптер находится в `links/apify.py`; фоновые задания, привязка заказа и UI от поставщика не зависят.

## Согласованность цены и заказа

`POST /api/link/market-jobs` принимает ссылку, размер и количество, возвращает UUID проверки. Celery выполняет сетевые запросы; браузер опрашивает `GET /api/link/market-jobs/{uuid}`. Для одной исходной карточки действует блокировка параллельных запусков; свежий результат Apify переиспользуется между размерами до двух минут. Данные импорта не считаются свежей проверкой. Общий дневной бюджет Apify сохраняется.

Успешная цена привязана к площадке/ID товара, размеру и количеству и действует пять минут. Клиент отправляет `quote_id` в `/api/link/order`. Сервер проверяет принадлежность цены варианту, срок, сумму в юанях и актуальность тарифа/курса. При изменении параметров требуется новая проверка. Цена «от» никогда не подставляется при отсутствии цены размера. Форма со скриншотом/явно указанной покупателем ценой остаётся отдельным прежним сценарием с проверкой агентом до выкупа.

Запоздалый ответ предыдущего размера или предыдущей формы не подменяет текущий расчёт. При изменении размера/количества заказ блокируется до нового результата. Прерванные или слишком долгие задачи дают конечную ошибку, а не бесконечный индикатор. Задания удаляются через сутки периодической задачей Celery Beat; контакты покупателей в них не хранятся.

## Обновление и проверка на сервере

Нужны работающие Redis, Celery worker/beat и существующий `APIFY_TOKEN`. Обычный `bash infra/update.sh` применяет миграцию `links.0007_marketlookup` и пересобирает сервисы. Новый API-ключ для текущего Apify не нужен.

После обновления проверить: карточка → размер → ожидание → цена либо честный отказ; смена размера и количества; вставка ссылки → фото → размер; вопрос ИИ про фото/размер. В сценарии отсутствия цены оплата по минимальной цене должна быть недоступна.

Сырой ответ подключённого провайдера для конкретного товара можно посмотреть существующей командой (один запуск расходует платный запрос):

```bash
docker compose -f infra/docker-compose.yml --env-file infra/.env exec backend \
  python manage.py market_raw 'ССЫЛКА_НА_ТОВАР'
```

Для просмотра результатов/ошибок фоновых задач — логи worker. API-ключи не публиковать.
