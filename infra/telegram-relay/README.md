### Подключение Telegram через отдельный VPS

Сайт, обработчик вебхука, очередь и база заявок остаются на сервере ASTTA. Зарубежный VPS принимает входящие вебхуки Telegram по `https://tg-relay.astta.ru/api/tg/webhook` и пересылает их в ASTTA с исходным секретом вебхука. Также можно направить через него исходящие запросы к Bot API. Порт базы и админку на VPS открывать не нужно.

После обновления ASTTA, перед переключением на VPS, запустите на сервере ASTTA:

```sh
cd /opt/astta
docker compose -f infra/docker-compose.yml --env-file infra/.env exec backend python manage.py telegram_check
```

Если исходящий Bot API доступен, а Telegram сообщает таймаут доставки, начните с входящего маршрута. Посредник должен сам получать ответ от ASTTA по HTTPS. Последняя ошибка в диагностике может относиться к более раннему запросу.

1. Создайте DNS-запись для отдельного имени, например `tg-relay.astta.ru`, ведущую на зарубежный VPS. Для этой конфигурации нужны свободные TCP-порты 80 и 443. Если VPS уже обслуживает другие сайты через Caddy, добавьте блок сайта из Caddyfile в существующий Caddy, вместо запуска второго экземпляра на тех же портах.
2. Скопируйте `Caddyfile` и `compose.yaml` в один каталог на VPS. Создайте в нём закрытый `.env` с `ASTTA_RELAY_DOMAIN=tg-relay.astta.ru` и `ASTTA_RELAY_KEY=<случайный ключ>`. Ключ можно сгенерировать командой `openssl rand -hex 32`. Права файла — 600.
3. Выполните `docker compose up -d` на VPS. Дождитесь выпуска TLS-сертификата. Неподписанный запрос к корню адреса посредника должен вернуть 404.
4. С зарубежного VPS проверьте `curl -sS -o /dev/null -w "%{http_code}\n" -X POST https://astta.ru/api/tg/webhook`. Ответ 403 без секрета ожидаем. Потом проверьте тот же путь через домен посредника, ожидается такой же 403. В `infra/.env` ASTTA укажите `TELEGRAM_WEBHOOK_ORIGIN=https://tg-relay.astta.ru`. Для исходящего маршрута при необходимости дополнительно укажите `TELEGRAM_API_URL=https://tg-relay.astta.ru` и `TELEGRAM_API_RELAY_KEY` с тем же ключом. Пересоздайте backend, worker и beat.
5. Запустите `python manage.py telegram_setup` в контейнере backend, затем `telegram_check`. Проверьте свежим сообщением `/start` или `/id` в боте.

Для отката уберите переменные посредника, пересоздайте контейнеры ASTTA и запустите `telegram_setup` повторно. Не включайте журналы доступа на посреднике без удаления токена из URL.
